#### 2. 数据清洗与重建脚本

8. 覆盖写入清洗后的 CSV。
9. 导入 MongoDB。
10. 使用 Qwen embedding 重建 ChromaDB 向量索引。

- 脚本要求显式传入 `--confirm-clear`，避免误清库。

#### 6. 混合检索

新增文件：
- `src/knowledge_base/hybrid_search.py`

1. MongoDB 全文检索。

5. 调用 rerank 模型重排序。
6. rerank 不可用时回退到融合排序。

### v2.7 — 简历润色 Agent MVP 落地与 PDF 简历增强规划（2026-06-24）

**状态**: 已提交  
**提交**: `739b63c`（`v2.7 feat(resume): add resume polish agent and frontend page`）  
**目标**：在原《简历润色工作流 Agent 设计文档》基础上，先交付可运行的简历润色 MVP，再扩展 PDF 简历读取、知识库岗位上下文增强和前端上传体验。

---

#### 1. 初始规划回顾

设计文档目标：
- 构建简历润色工作流 Agent，作为 HK-JobMarket-Analyzer 内置功能模块运行。
- 工作流节点：简历解析 → JD 分析 → 岗位匹配 → 差距分析 → 润色生成 → 评分验证。
- 复用现有基础设施：
  - `LLMConfigManager`：读取 LLM API Key / Base URL / Model。
  - `RoleClassifier`：目标 JD 角色分类。
  - `VectorStore`：从 ChromaDB 召回相似岗位。
  - 知识库岗位数据：作为香港 IT 市场表达与技能关键词参考。
- 模型配置原则：
  - 简历润色 Agent 不提供独立模型配置。
  - 统一使用系统设置页中的 LLM 配置，即 `LLMConfigManager` 管理的 API Key / Base URL / Model / Timeout。
  - 前端简历润色页面不暴露模型选择项；如需换模型，应到系统设置页修改全局 LLM 配置。
- 输出产物：
  - 逐段润色建议。
  - 技能差距分析。
  - JD 关键词覆盖建议。
  - 相似岗位参考。
  - 多维评分报告。

### 1. JobResearch：知识库驱动的岗位调研

目标：先用本地 MongoDB / ChromaDB / HybridSearch 构建“香港市场岗位画像”，后续再可选接入 WebSearch 补充具体公司官网、最新 JD、面经和新闻。

推荐分层：
```text
JobResearch
├─ KB Research：基于本地岗位知识库分析香港 IT 市场共性需求
└─ Web Research：后续可选，补公司级、部门级、最新面经与动态
```

知识库可支撑的调研内容：
- 目标岗位画像：同类岗位常见 title、职责、年限、学历、语言要求。
- 核心能力关键词：从 `skills`、`jd_text`、`kb_document_text` 聚合高频技能。
- 技术栈趋势：Python、AWS、Azure、LangChain、RAG、MLOps 等出现频次。
- 角色方向判断：AI 应用开发、后端、DevOps、数据、Technical PM 等。
- 香港市场措辞：常见英文 JD 表达、responsibilities / requirements 句式。
- 相似岗位样本：召回 5-10 条代表性岗位作为依据。
- 简历改写靶心：收敛成 3-5 个核心能力关键词。
- 置信度与缺口：如果样本少，标注低置信，不把市场画像伪装成具体公司结论。

边界：
- 知识库能回答“香港市场类似岗位通常要什么”。
- 单靠知识库不能回答“某公司这个具体岗位最新要求是什么”。
- 用户提供 JD 时，JD 是最高优先级；未提供 JD 时，知识库生成“市场岗位画像”。

### 2. 当前简历工作流与 `get-job.skill` 的主要差距

#### 2.1 缺 Stage 0 输入体检

`get-job.skill` 在进入调研或改写前会先判断输入状态：
- 目标公司 / 岗位是否明确。
- 目标市场 / 语言是否明确。
- JD 是否完整。
- 简历是否完整。
- 是否已经投递。
- 是否已有面试轮次。

建议新增 `InputHealth` 层：
```text
InputHealth
- target_company
- target_role
- target_market
- jd_status
- resume_status
- application_status
- interview_stage
- assumptions
- blocking_questions
```

状态分级：
- `Complete`：目标岗位、市场/JD、简历、投递状态足够明确，直接进入对应阶段。
- `Workable`：有缺口但不阻塞，自动推断、知识库补齐、低置信标注后继续产出。
- `Blocked`：缺少目标岗位或简历正文等硬输入，继续会误导，只问最少必要问题。

#### 2.2 缺岗位调研作为润色前置阶段

当前 v2.8 的 `market_context` / `market_insights` 多作为润色过程中的内部上下文。下一步应独立成 `JobResearch` 阶段，作为简历改写和面试准备的共同输入。

阶段产出建议：
- `岗位调研.md` 或前端 `岗位调研` Tab。
- 目标市场与来源覆盖说明。
- 3-5 个核心能力关键词。
- 同类岗位高频技能与职责。
- 隐性门槛与风险点。
- 简历改写靶心。
- 低置信 / 待确认缺口。

#### 2.3 缺“简历 bullet → 面试准备”的下游闭环

`get-job.skill` 要求最终简历每一条 bullet 都进入面试准备，并具备：
- 30 秒讲法。
- 60-90 秒展开版。
- 2-4 个追问。
- 证据口径。
- 二三层追问兜底。
- 不能说什么。
- 风险等级。

建议新增 `ResumeBulletInventory`：
```text
ResumeBulletInventory
- bullet_id
- final_text
- target_capability
- evidence_source
- evidence_confidence
- talk_track_30s
- follow_up_questions
- risk_notes
- fallback_answer
```

前端可新增结果 Tab：`面试深挖`。

#### 2.4 缺证据化审计与风险地图

当前 prompt 已强调“不编造经历”，但尚未结构化追踪 claim 证据。

建议新增 `ClaimEvidence`：
```text
ClaimEvidence
- claim
- claim_type: number / role / skill / achievement
- source: resume / project_library / user_confirmed / inferred
- confidence: strong / medium / weak / risky
- action: keep / soften / remove / ask_user
- interview_strategy
```

处理原则：
- 每个数字、强动词、成果 claim 都要有来源或降级策略。
- 讲不清来源的数字模糊化或删除。
- 学历、在职时间、职位名称、公司名等背调硬信息不改。
- 市场 JD 中出现的技能不能直接写成用户经历，除非用户简历或项目素材中已有证据。

#### 2.5 缺质量闸门和回归评测

`get-job.skill` 把质量拆成 P0 / P1 / P2，并提供 `quality_check.py` 与固定回归场景。当前项目已有功能测试，但缺求职语义层面的 eval。

建议质量闸门：
- P0 红线：造假、背调硬信息改动、低质量来源冒充事实、过度包装、标签泄漏。
- P1 核心质量：JD 核心能力必须映射到真实经历；每条最终 bullet 必须有面试讲法和证据状态；低置信内容必须标注。
- P2 体验质量：文件名、结构、扫读体验、语言自然度。

建议回归场景：
- 完整 JD + 完整简历。
- 无 JD，仅目标岗位。
- 简历已投，不允许改写，只准备面试。
- 用户承认某个数字记不清。
- PDF 简历 + 知识库模式。
- 香港岗位 + 英文 JD。
- 轮次未知，不能硬生成 HR 面 / 二面 / 三面。

### 3. 用户长期素材库规划

参考 `job-hunt-copilot-public.skill`，建议为简历 Agent 增加长期素材层：

```text
resources/
├─ self_profile.md      # 用户背景、求职偏好、技能标签
├─ resume_base.md       # 全量基础简历
└─ projects/            # 项目素材库
   └─ {project_name}.md
```

项目模板字段：
- 项目名称、组织、时间周期、角色与团队规模。
- 背景与问题。
- 从 0 到 1 的关键过程。
- 结果与数据。
- 原始素材区。
- 能力标签。

用途：
- 按 JD 从项目库中选择 2-4 个最相关项目。
- 将真实经历翻译成目标岗位语言。
- 为每条 bullet 提供证据来源。
- 支撑面试项目讲稿和 STAR 结构回答。

隐私策略：
- 默认不自动持久化用户上传的简历原文。
- 项目库 / 基础简历保存前应由用户确认。
- 生成版本可保存摘要、结构化字段和用户确认后的内容，不保存未经确认的敏感原文。
