### 2. 数据清洗与重建脚本

新增脚本：

- `scripts/rebuild_jobsdb_knowledge_base.py`

脚本流程：

1. 读取 JobsDB 原始 JSON。
2. 调用项目现有 `CleaningPipeline` 进行清洗。
3. 调用项目现有保险销售识别逻辑 `is_insurance_sales`。
4. 调用 `RuleBasedSkillExtractor` 抽取技能。
5. 生成面向知识库索引的 `kb_document_text`。
6. 处理重复 `job_id`，保留 `original_job_id` 并追加去重后缀。
7. 清空 MongoDB、ChromaDB、`data/cleaned/jobs.csv`。
8. 覆盖写入清洗后的 CSV。
9. 导入 MongoDB。
10. 使用 Qwen embedding 重建 ChromaDB 向量索引。

安全控制：

- 脚本要求显式传入 `--confirm-clear`，避免误清库。

向量库变化：

- 使用 batch upsert 写入向量。
- 优先索引 `kb_document_text`，不存在时回退到 `jd_text`。
- 修复原有 `texts.append(...)` 被注释吞掉导致正文不入库的问题。

### 5. Rerank 接入

新增文件：

- `src/knowledge_base/reranker.py`

实现：

- 调用硅基流动 `/v1/rerank` 接口。
- 默认模型：`Qwen/Qwen3-Reranker-8B`
- 对 Qwen3 reranker 增加 `instruction` 参数。
- 失败时返回空结果，由混合检索回退到融合分数排序。

### 6. 混合检索

新增文件：

- `src/knowledge_base/hybrid_search.py`

检索流程：

1. MongoDB 全文检索。
2. ChromaDB 向量检索。
3. 按 `job_id` 合并候选。
4. 计算融合分数：
   - 默认语义权重：`0.7`
   - 默认关键词权重：`0.3`
5. 调用 rerank 模型重排序。
6. rerank 不可用时回退到融合排序。

补充能力：

- MongoDB 不在线时，自动 fallback 到 `data/cleaned/jobs.csv` 做关键词检索。

## 注意事项

1. `.env` 已写入本地硅基流动 API Key，但 `.env` 被 `.gitignore` 忽略，不会提交。
2. API Key 曾出现在对话中，建议后续在硅基流动控制台轮换密钥。
3. 当前 MongoDB 数据依赖 Docker volume `mongo_data`。
4. 如果删除 MongoDB 容器但保留 volume，数据仍在；如果删除 volume，需要重新执行重建脚本。
5. 如果在无网络或受限网络环境执行重建，embedding 阶段可能失败，ChromaDB 会被清空后无法恢复；需要确保硅基流动 API 可访问后再执行。
